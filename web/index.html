The inversion

Every "AI wallet" asks you to trust the agent.
WARDEN doesn't.

The AI only proposes. A deterministic, fail-closed Guardian re-derives the truth on-chain and holds the leash. The agent is powerful — and powerless to do harm.

✕ The usual approach

  • ✕Agent holds a broad wallet key — can drain it
  • ✕You trust the agent's own risk numbers
  • ✕Reasoning is off-chain — unverifiable, deniable
  • ✕One key, one agent, no referee
  • ✕No compliance path → no institutional capital

✓ WARDEN

  • ✓Agent holds a non-transferable capability object, not a key — and never the withdraw path
  • ✓Chain re-derives risk on-chain from raw Pyth + DeepBook — diverge → freeze
  • ✓Action and reasoning sealed to Walrus with a three-proof receipt — replay anything
  • ✓Independent critic agent signs with its own separate key
  • ✓Protocol-level KYC token + gated venues → institution-ready
Architecture

Seven layers. One leash.

Each layer is load-bearing under a single thesis — not a feature dump. Hover a layer. Layer 2 is the heart: the chain never trusts the AI.

L0
Onboarding & custody — non-custodial by construction
module: vault
zkLogin + sponsored gas (deposit with Google, no seed, no gas). Funds live in a user-owned Vault; the fleet gets a no-withdraw boundary. Deposit mints a PT/YT split priced on DeepBook; idle buffer earns yield-in-flight from second one.

L1
Authority is an object, not a key — object-capability
module: policy
A non-transferable capability minted without store (unforgeable, unsellable). Scope enforced by Move's type system + a hot-potato ActionReceipt that must be consumed by a policy-checked settlement in the same PTB — over-scope is structurally impossible. Recursive work-graph delegation with a generation revocation lattice: revoke the parent, the whole fleet dies.
non-transferable cap (no-store)hot-potato enforcementadapter-gated permitsrevocation latticeadmin can't move funds
L2
The chain never trusts the AI♥ heart
modules: guardian · critic
The AI proposes an unsigned intent. A deterministic, fail-closed Guardian re-derives every risk number on-chain from raw Pyth + DeepBook order-book state. The agent is clamped to the safe direction only; fills above a live-SVI ceiling are rejected on-chain. An independent critic agent signs with its own key. If the on-chain re-derivation diverges from the agent's claim → the position freezes; only the DAO can unfreeze.
on-chain risk re-derivationsafe-direction-only clampindependent critic (own key)divergence → freezeWYSIWYS + scam-clone detection
L3
Structured-product engine — it hedges itself
module: strategy
A hedged-carry loop (PLP carry minus OTM crash insurance, bounded drawdown). Trades volatility itself via the first on-chain variance / log-contract (VIX-style replication, settled from one Pyth read). Strategies are forkable, composable on-chain objects compiled from NL/visual/YAML through a typed Financial IR, priced via devInspect zero-gas quotes.
hedged-carry (PLP + OTM)on-chain variance (VIX)Financial IR + forkable strategystrategy marketplaceon-chain American options
L4
Everything is verifiable — memory, reasoning, provenance
module: ledger
Every tick: recall → reason → execute under policy → attest on-chain → store on Walrus. Each decision yields a three-proof receipt (Sui digest + Walrus blob + TEE attestation). The full reasoning is sealed and replayable. Cited sources are frozen byte-for-byte; the track record is tamper-evident, non-backdated, monotonic-no-delete — you can't quietly drop your losing trades.
three-proof receiptreplayable reasoningTLSNotary provenancetamper-evident track recordlive vol terminal, no mock data
L5
Compliance & confidentiality — institution-ready
modules: compliance · oracle
A closed-loop KYC token (transferable only between verified holders, enforced at protocol level) + compliance-gated venue adapters → compliant and liquid on DeepBook/CLMM/DLMM. Confidential Transfers hide sensitive amounts; private risk models stay encrypted under Seal threshold-IBE + TEE attestation. Real-world facts become TEE-signed, on-chain-checkable results; disputes resolve through a Move-native optimistic oracle.

L6
Continuity · governance · distribution
modules: inheritance · prize
Dead-man-switch inheritance: a heartbeat keeps a position yours; on prolonged inactivity a Clock-gated seal_approve lets a beneficiary inherit it. A no-loss prize layer (commit-reveal + native ecvrf). An x402 rail where other agents pay per-query and the balance change is the receipt. MCP server + SDKs + a Walrus-Sites front-end with byte-level integrity.
